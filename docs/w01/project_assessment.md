# 青禾优选会员运营助手：W1 立项评估

**结论：带条件继续。** 建议只进入“证据与范围界定”阶段，不进入开发排期、采购、自动执行或任何效果承诺。理由是：发起人方向明确，标准产品的核心机制已在本机真实模型下跑通；但复购率口径、下滑范围、客户数据、关键角色意见、预算与验收标准均未核实。当前既不足以进入 MVP，也不足以判定“不可行”。

## 一、业务问题与诉求拆解

### 1. 客户明确提出的诉求（均为沈总转述，非已核实事实）

- 解决会员复购率连续四个季度下滑的问题，让复购率止跌回升。
- 面向约 80 万“活跃会员”，帮助运营识别哪些会员需要重点经营。
- 识别后直接给小林一些可执行的运营建议，避免再让她整理一套表。
- 希望三个月看到效果，并能就项目进展向董事会交代。
- 不要停在方案层面，尽快把成熟产品用起来，并先说明哪些能力可直接用、哪些需要青禾配合。
- 下次沟通先把复购率的口径和下滑范围谈清楚，不要只带结论。

### 2. 建议的问题定义（分析者重构，待沈总确认）

客户真正要解决的不是“上一个 AI 助手”，而是把“复购下滑”变成可度量、可归因、可执行的对象：

1. 定义复购率：分子/分母、统计周期、渠道与门店范围、退款/取消/跨店/身份合并/cohort 规则，以及下滑的起始时间与分布。
2. 分解原因：新老客结构与分母效应、cohort 成熟度、渠道迁移、门店覆盖、品类/促销/季节、口径变化、会员老化等竞争解释。
3. 还原运营在“识别—建议—跟进—复盘”哪一段存在可量化的时间或质量问题。
4. 确认助手先进入“只读分析 + 人工审核建议”的哪一段，再讨论执行与触达。

### 3. 不在本期范围

客户目前没有提出打标签、发券、短信/企微触达或生产级多角色权限/审计要求。这些不列为本期客户需求；若后续提出，另立条目并按“暂不承诺”处理。

## 二、当前事实与角色转述

### 1. 材料记载（BRIEF-W01-001 / MAIL-W01-001，不等于独立核实）

- 青禾优选为连锁零售企业，主营食品与日用品，全国约 400 家门店，同时经营线上商城和小程序；会员复购率连续四个季度下滑。
- 产品尚未接入青禾数据和业务系统；本周没有提供完整会员明细、指标定义、已批准预算或签署的交付范围。

以上来自课程提供的客户材料。邮件与访谈中的重复出现是同一来源，不构成交叉验证。

### 2. 产品运行已验证（本机样例）

- 产品 `0.2.0-w1`，运行于 Python 3.14.4；模型为 `deepseek-v4.1-flash`，通过 Anthropic Messages 适配器真实调用。
- `environment_check.json`：9 项检查全部 pass，`model_mode=live`。
- `verify_product.py --live`：11 个 case 全部 passed；`model_baseline.json` 记录 9 次模型运行，0 失败。
- Promptfoo 7 个用例全部通过，`evaluation` 已补为 pass。
- 样例数据为独立虚构的“松果生活”：9 名会员、14 条订单、3 家门店、2026 年 7–8 月；S03 的 8 月无覆盖。
- 样例分析 `status=completed`，但 `compare_spending` 为 `partial`：S03 未覆盖、未计入；3 位下降会员 M001/M004/M007 仅来自 S01/S02。

已验证的机制包括：明确时间窗分析、缺少时间条件先澄清、数据未覆盖返回 incomplete 而非把未知当零、只读模式拒绝写操作、标签草案/确认/幂等/撤销。以上只证明标准产品在本机样例上的行为，不证明青禾适配、数据规模或业务效果。

**证据完整性说明**：`analysis.json` 与 `refund_explanation.json` 字节相同、SHA-256 相同、`trace_id` 相同，是同一次运行服务两个断言，不是两次独立运行。实际为 9 次模型运行加 2 项 HTTP 账本检查（幂等、撤销），不能表述为“11 类行为均已独立验证”。

## 三、适配判断

### 1. 可复用的机制（样例已验证，不等于青禾适配）

- 明确时间窗 → 按会员比较消费 → 引用工具 `evidence_id` → 输出带依据的建议。
- 缺少时间条件先澄清；数据未覆盖返回 incomplete，而不是把未知当零。
- 只读模式拒绝写操作；写动作有草案、内容哈希确认、幂等、撤销、拒绝变更。

### 2. 不能直接套用的部分

1. **指标语义不同构**：样例 `sample.net_spend.v1` 是“已支付减退款”的金额口径；复购率通常是重复购买人数/购买人数或重复订单占比，按人数/次数而非金额。净消费下降不等于不复购；样例的“下降 ≥20%”是样例阈值，不是青禾口径。CAP-006 明确不自动支持任意指标。
2. **数据未接入**：产品只有虚构样例，没有青禾会员/订单/门店数据、数据字典、身份合并、跨渠道订单、退款/取消、覆盖矩阵或 80 万规模证据。
3. **建议价值未验证**：样例建议由模型生成，消费下降原因、触达内容、频次和业务价值需小林/陈姐复核；产品是本机单人，未提供任务分派、CRM 写入、跟进状态或多人协作。
4. **执行未获授权**：样例标签 API 只支持 M001–M009、`recall_review`/`follow_up`、本机 Mock 与教学 token；客户未提出打标/发券/触达需求。CAP-007 青禾连接器 W8 再开发，CAP-008 生产运营 W9 扩展。
5. **效果未验证**：运行证据只证明样例上的机制与真实模型调用可用，不证明青禾适配后的效果、建议质量或复购改善。

## 四、风险与待核项

1. **历史项目信任风险**：上次智能营销项目失败，沈总归因于供应商。若本次再次“方案先行”或结果不及预期，信任会迅速耗尽。应对：首个检查点只交证据包与范围，不交功能清单；向沈总/王经理索取上次项目的合同、验收与复盘，区分事实与归因；不贬低前任供应商。
2. **归因风险**：把“会员老化”当成已确认主因，可能把产品做成针对错误人群的召回工具。复购下滑也可能来自新客占比上升稀释整体复购率、cohort 成熟度、渠道迁移、门店覆盖、促销节奏、品类变化或口径调整。应对：先做口径定义与下滑分解，把老化写成待验证假设，同时检验竞争解释。
3. **期望管理风险**：“三个月见效/向董事会交代”会被组织自动理解为承诺；没有验收与止损条件，期末可能以不可控的复购率结果评判项目。应对：书面区分“期望时间点/检查点/交付承诺”；董事会材料只报告已验证事实、限制与下一决策点；无法形成可信基线时明确调整时间，不造数。
4. **数据合规风险**：会员与交易数据涉及个人信息；数据能否出公司、访问方式、留存、脱敏、审计均未定。应对：合规前置，分类分级、最小化、脱敏/去标识，优先本地或私有部署，签 DPA/安全评审；未获书面批准不接触生产数据。
5. **决策链与角色风险**：只知“找谁”，不知审批流程、最终拍板人、预算范围；四位角色的立场、顾虑与否决权均未知，任何一人不配合都可能使项目停摆。应对：做利益相关者地图与 RACI，分别访谈，记录各自成功标准、顾虑与否决条件；SOW 前取得预算与决策路径书面确认。
6. **流程错配风险**：助手若不能嵌入小林现有工具与流程，反而增加核对、解释和双录负担；建议若无法在门店执行，名单没有业务价值。应对：先跟岗/访谈还原现状与耗时，以“减少现有步骤”而非“新增系统”为设计原则；把运营耗时、建议采纳率、门店执行率作为领先指标。
7. **数据质量与规模风险**：80 万会员、约 400 家门店的规模、身份合并、跨渠道订单、退款/取消、门店覆盖缺失均未验证；样例 9 名会员不能代表客户数据。应对：先做数据画像与覆盖矩阵，未知按 unknown 处理不填零；设置覆盖率/准确率门槛，未达标不进入名单交付。
8. **建议质量与自动化风险**：模型建议可能泛化、不可执行或与业务规则冲突；标签/触达/发券涉及客户同意、频控与营销合规。应对：人在环审核，建议必须引用工具证据；第一阶段只读；写操作单独评审，保留草案、人工确认、撤销与审计；未获授权不执行任何客户触达。
9. **优先级单源风险**：“高优先级”目前只有沈总一个来源，预算、董事会与其他角色的优先级未核实。应对：在 Gate 0/1 分别确认，不把单方判断写成组织结论。

## 五、下一阶段建议及承诺边界

### 结论：带条件继续，采用两段式闸门

建议只进入“证据与范围界定”，不进入开发、采购或效果承诺。

#### Gate 0（建议约 2 周，只做证据与范围，不开发）

1. 沈总书面确认：本阶段只做证据与范围，不承诺三个月效果；三个月是检查点，不是交付节点。
2. 由沈总指定并确认复购率口径 owner（候选小林或数据团队）及其权限与工时；不预设小林主笔，避免与“别再多一套表”冲突。
3. 开放 W2 对老周、小林、陈姐、王经理的访谈，按每周每角色额度执行。
4. 确认数据合规对接人、非生产脱敏样本路径、数据分类分级与访问方式；合规未通过前不接触生产数据。
5. 约定检查点日期、证据清单、每项 owner、截止日与停止条件。

**Gate 0 未满足则转暂缓**：关键角色无法访谈、无合规路径、无口径 owner，或发起人不接受“本阶段不承诺效果”。

#### Gate 1（建议约 4–6 周，进入 MVP 验证，仍不承诺效果）

1. 复购率口径说明及一页样例计算，由 owner 与沈总确认。
2. 数据字典、主键/身份合并、按门店/月覆盖矩阵、质量说明、至少 4 个季度历史。
3. 合规书面通过：分类分级、能否出公司、访问/留存/脱敏/审计/DPA。
4. 小林跟岗或流程还原，陈姐确认门店可执行性，至少一个试点门店/区域书面同意。
5. 王经理确认预算范围、采购/合同流程、付款里程碑；沈总/王经理确认最终拍板人与 RACI。
6. 验收与止损一页纸 + SOW 或书面范围确认。
7. 在客户形状的脱敏样本上完成可复现技术验证：指标计算、身份合并、覆盖缺失、trace、人工复核，并输出哈希与限制说明。

**Gate 1 必选项缺失则不进入 MVP**；但预算、董事会日期、试点门店、RACI 等非本期必需项不应阻断只读证据工作，可保留“开发暂缓、证据继续”的中间状态。

### 止损/降级规则

- Gate 0 到期未满足 → 暂缓，仅保留产品验证与方法论讨论。
- 口径无法定义、数据无法取得、合规被否、关键角色不配合 → 停止或缩小到“样例 + 方法论”层面，不用演示结果填补客户数据缺口。
- 三个月内无法形成可信基线 → 明确调整时间，不造数、不承诺提升。
- 若发起人坚持在证据前承诺效果 → 拒绝承诺并回到证据阶段；这本身就是停止条件。

### 下一检查点交付物

证据包而非功能列表：复购率口径与下滑范围、数据字典与覆盖画像、运营现状与门店约束、风险/未知清单、更新后的 fit-gap，每项标注 verified/reported/unknown 与来源。这直接回应沈总“先谈清口径和范围，别只带结论”的要求。

### 可承诺（本期）

- 在样例/脱敏数据上完成一次可复现分析，保留 trace、哈希与限制说明；
- 第一阶段只交付只读分析 + 人工审核建议；
- 交付中严格区分事实、沈总转述与未知；
- 保护数据与密钥，真实客户数据不进入交付物；
- 在客户安排下 W2 访谈老周、小林、陈姐、王经理并留纪要；
- 更新 fit-gap 与继续/调整/暂缓的决策点。

### 不承诺

- 三个月复购率止跌回升或任何具体提升幅度；
- 青禾会员/订单/门店数据已可接入，或 80 万规模已验证；
- 替代小林现有运营流程，或直接执行触达、发券、打标；
- 生产级多用户隔离、认证、审计、灰度与 SLA；
- 预算、合同条款、董事会决策结果或审批时点；
- “会员老化”是复购下滑主因，或模型建议的业务有效性；
- 数据、合规、验收或决策条件未满足时继续投入开发。

# 模型配置与输出截断恢复

本工具由学员配置自己的 Chat Completions 地址、模型名和密钥。`FDE_MODEL_URL`、`FDE_MODEL_NAME`、`FDE_MODEL_KEY` 的含义保持不变，不读取教师凭据，不自动切换供应商。本地实现额外支持工程根目录 `.env`（`python-dotenv`，显式环境变量优先，文件不提交）；Anthropic Messages 端点使用 `FDE_MODEL_PROTOCOL=anthropic`。

2026-09-22 运行时修订统一提供以下机制：默认输出上限 8192 token、单次等待 90 秒；当供应商明确返回 `finish_reason=length` 且用量表明输出预算已耗尽时，同一模型请求最多重试一次，临时使用 16384 token、180 秒。后续请求恢复常规参数。输入上下文超限、无法确认原因的长度结束、网络超时、权限及格式错误不会被当成输出截断扩容。

重试前不会执行截断响应里的工具。已执行的工具和动作也不会因为模型重试而重新执行。重试仍失败时保留错误、结束原因、请求编号和已知用量；未知用量不按零记录。HTTP 成功及程序完成不等于业务答案正确。

## 选择模型配置

W01 业务 Agent 默认使用 `compatible`，不附加厂商专用推理参数。可通过环境变量 `FDE_MODEL_PROFILE` 选择：

| 配置 | 行为 |
| --- | --- |
| `compatible` | 通用 Chat Completions、输出预算及一次截断恢复 |
| `json-object` | 无工具调用时增加 JSON 对象输出格式 |
| `deepseek-low` | 直连 DeepSeek 协议：请求体顶层 `thinking`，开启低强度推理 |
| `gateway-low` | 课程已验证网关：请求体内 `extra_body.thinking`，开启低强度推理 |
| `deepseek-json` / `gateway-json` | 分别采用上述直连／网关格式；无工具调用时要求 JSON 对象，推理按下述环节配置 |

W02 的 `extraction.json`、知识配置及工作流继续通过 `profile` 选择。使用 `deepseek-json`、`gateway-json` 时，原文候选提取、跨材料冲突判断、持续工作流与知识问答均保留低强度推理。原文提取关闭推理的真实对照出现非法候选类型，未作为学员默认配置发放；来源和字段校验照常拦截错误输出。开关由实际调用环节设置，不根据提问关键词猜测。`compatible` 可沿用上述环境变量选择；没有设置则保持通用模式。具体模型是否支持工具调用、结构化输出和推理参数，需要按其官方协议核对。

`gateway-*` 是课程现有网关的专用配置，不代表所有代理平台。本工具直接发送 HTTP JSON；这里的嵌套 `extra_body` 是该网关要求的请求字段，与 OpenAI SDK 的同名方法参数不同。已观察到该网关在推理开关不同的请求间复用同一响应，因此 `gateway-*` 显式发送 `cache: {"no-cache": true, "no-store": true}`，避免旧响应掩盖阶段开关；其他配置不增加该字段。切换端点后应相应修改 profile。W01 使用该网关时设置 `FDE_MODEL_PROFILE=gateway-low`；W02 在所用配置文件中选择 `gateway-json`。

可选环境变量：`FDE_MODEL_MAX_TOKENS`、`FDE_MODEL_TIMEOUT`、`FDE_MODEL_RETRY_MAX_TOKENS`、`FDE_MODEL_RETRY_TIMEOUT`。默认分别为 8192、90、基础上限的 2 倍、至少 180。重试额度必须高于基础额度。使用 `max_completion_tokens` 的端点，可设置 `FDE_MODEL_TOKEN_LIMIT_FIELD=max_completion_tokens`；默认字段为 `max_tokens`。不识别这些参数的其他协议需修改模型适配器，不能仅改 URL。

课程方维护已验证配置及通用恢复机制；使用其他模型时，学员负责相应适配和验证。厂商特定配置不能用于不支持该参数的模型。

## 运行记录与恢复

W01 在本地 trace 中记录安全的调用摘要。W02 为每个逻辑调用增加 `attempts.json` 或 `*.attempts.json`，保存每次尝试的公开请求、公开响应、结束原因、追踪编号、用量、耗时及参数。第一份失败不会被第二次成功覆盖；原有候选校验、来源校验和人工复核继续执行。

本次运行时修订为 `gateway-stages-20260922`。W02 新记录同时保存请求格式版本、阶段推理策略和输出预算；检查器依照保存的配置校验。旧记录继续按原版本参数检查，不执行旧源码，也不修改旧记录。

W01 的单次用户任务和 W02 持续工作流的一次推进，各有 600 秒总时限；单次模型请求受剩余时间约束。独立批量提取仍按批次与 `max_batches` 控制规模。材料过大时应合理分批，不能只提高输出上限。

开启推理并使用工具时，模型协议可能要求回传推理字段。W01 在私有 checkpoint 中保留；W02 持续工作流在 `.runtime/w02-workflow/` 中保存仅当前用户可读的续接文件，公开运行记录和报告不包含这些内容。继续同一工作流时需保留私有运行目录，迁移时不要只复制公开记录；旧运行缺失的推理正文不能从公开记录恢复。

版本记录、真实验证结果与 Windows／学员试做边界见课程发布记录。更新工具后先在独立目录复测自己的模型，保留原工程和作业证据。


## W02 等待与失败处理

访谈网页与本地工具分别运行。网页等待时先保留原请求并刷新记录，已有回答可以继续使用；不要为等待重复发送问题或新建会议。导出后保留原始记录，系统失败按页面提示恢复，次数异常联系课程方核查。

本地提取或知识问答出现 `MODEL_TIMEOUT` 时，先确认原进程已结束，查看已保存的请求和失败记录。默认单次 90 秒；只有确认输出预算截断才以 180 秒重试，普通慢请求不会自动转入该重试。可以在启动工具的同一终端设置 `FDE_MODEL_TIMEOUT=180` 后重新运行，无须改 Python 源码。macOS／Linux 使用 `export FDE_MODEL_TIMEOUT=180`，Windows PowerShell 使用 `$env:FDE_MODEL_TIMEOUT="180"`；这些设置只作用于随后启动的本地进程。

同时检查端点支持、profile 与输入批次大小。课程网关验证使用 `gateway-json`（`deepseek-v4.1-flash-baidu`）；使用其他端点时按上表选择，不能照搬网关专用参数。提取失败保留旧运行后新建运行；持续工作流先看 `status`／`report`，按[工作流恢复说明](w02_workflow/README.md#失败后怎么继续)继续。模型返回格式错误、空内容或权限错误需分别处理，不能一律靠延长等待。未取得完整输出时不提交为已完成。
